# 홈페이지 온보딩 해석 규칙

## 목적
계약이 완료된 홈페이지 제작 고객의 온보딩 데이터를 분석하고, 제작에 필요한 사업 사실을 정리한 뒤, 최소한의 추가질문만으로 실제 기획이 가능한 상태를 만든다.

이 단계의 목적은 디자인이나 구현이 아니라 `고객이 제공한 사실을 제작 가능한 정보로 정리하는 것`이다.

## 핵심 원칙

### 1. 사업 사실과 제작 판단을 분리한다.

고객에게 받아야 하는 사업 사실:
- 실제 서비스
- 실제 서비스 범위
- 실제 가격
- 실제 추가비 조건
- 실제 정책
- 실제 운영 지역
- 실제 실적
- 실제 후기
- 실제 인증
- 실제 경력
- 실제 프로세스
- 실제 보증/보완 조건

이 정보는 임의로 만들지 않는다.

제작자가 판단할 수 있는 항목:
- 페이지 구조
- 섹션 순서
- 정보 우선순위
- CTA 배치
- Hero 표현
- 카피 표현
- FAQ 구성
- 이미지 배치
- 디자인 방향
- 레이아웃
- 모션
- 컴포넌트 방식

이 항목은 고객에게 불필요하게 질문하지 않는다.

### 2. 모든 부족한 정보를 질문하지 않는다.
질문은 다음 조건일 때만 한다.
- 사실이 없으면 서비스 내용을 잘못 표현할 위험이 있는 경우
- 사실이 없으면 가격/정책을 잘못 공개할 위험이 있는 경우
- 사이트 핵심 전환 구조를 정할 수 없는 경우
- 공개 시 허위 정보가 될 가능성이 있는 경우

단순히 디자인을 정하기 위해 질문하지 않는다.

### 3. 추가질문은 최대 3개다.
질문 우선순위:
1. 제작을 막는 핵심 사실
2. 고객의 구매 판단에 직접 영향을 주는 사실
3. 공개 시 위험이 있는 사실

3개 미만이면 억지로 채우지 않는다.

### 4. 고객이 "알아서 해주세요"라고 해도 사실을 만들지 않는다.
잘못된 처리:
- 고객이 가격을 안 줬으므로 시장 평균 가격을 작성
- 후기가 없으므로 실제 후기처럼 보이는 가상 후기 생성
- 보완 정책이 없으므로 무료 재방문 정책 생성

올바른 처리:
- 가격은 상담 문의 처리
- 실제 후기 영역은 자료 대기
- 정책은 확인 필요 상태로 표시

### 5. 자료 부족과 정보 부족을 구분한다.

정보 부족:
- 가격이 정해지지 않음
- 서비스 범위가 불명확
- 정책이 없음

자료 부족:
- 실제 사진 미제공
- 후기 캡처 미제공
- 로고 파일 미제공
- 전화번호/URL 미연결

자료 부족 때문에 기획을 중단하지 않는다.

## 상태 판정

### READY
추가질문 없이 기획 가능

### NEED_INFO
사업 사실 확인이 필요. 최대 3개 질문 생성

### WAITING_ASSETS
기획은 가능하지만 실제 자료가 아직 없음

### MANUAL_REVIEW
계약 범위, 법적 문제, 기술 구현, 고객 요구가 서로 충돌

## 온보딩 분석 출력
1. 사업 핵심 요약
2. 주요 서비스
3. 주요 고객
4. 고객의 핵심 문제
5. 고객이 원하는 결과
6. 차별점
7. 신뢰 요소
8. 가격/정책/범위
9. 주요 CTA
10. 현재 자료 상태
11. 확인이 필요한 사실
12. Status
