# Creative Build Brief 생성 규칙

## 목적
온보딩과 최종기획의 결과를 단순 요약본으로 Codex나 디자인 스킬에 전달하지 않는다.

최종 전달물은 제작자가 실제 화면과 스크롤 경험을 상상할 수 있는 서술형 `Creative Build Brief`여야 한다.

이 Brief는 다음 질문에 답해야 한다.
- 이 사이트는 누구를 위한 것인가?
- 방문자는 어떤 걱정이나 욕구를 가지고 들어오는가?
- 어떤 순서로 설득되어야 하는가?
- 첫 화면에서 무엇을 느끼고 무엇을 해야 하는가?
- 각 주요 구간은 어떤 역할을 해야 하는가?
- 어떤 실제 사실과 Proof를 강조해야 하는가?
- 어떤 레이아웃과 시각적 리듬이 필요한가?
- 어떤 감정으로 마지막 CTA에 도달해야 하는가?

## 입력 자료
Creative Build Brief는 다음을 결합해서 생성한다.
1. 확정된 사업 FACT
2. 최종기획의 전환 전략
3. 선택된 사이트 구조
4. 디자인 모드
5. 선택된 디자인 방향
6. 실제 자료 / DESIGN MOCK ASSET 상태
7. 구현 플랫폼 및 기술 제약

## 1. 데이터 목록이 아니라 경험으로 서술한다.
잘못된 예:
- 업종: 청소
- 톤: 신뢰
- 색상: 그린
- CTA: 견적 요청

올바른 예:
“입주를 앞둔 고객이 가격과 추가비, 청소 품질에 대한 걱정을 가지고 들어오고, 스크롤하면서 그 불안을 하나씩 해소한 뒤 견적을 받아봐도 되겠다고 느끼는 경험으로 설계한다.”

## 2. 방문자의 감정 변화를 정의한다.
사이트 진입 시:
- 무엇을 걱정하는가
- 무엇을 모르는가
- 무엇을 의심하는가

사이트 종료 시:
- 무엇을 이해했는가
- 무엇을 신뢰하게 되었는가
- 왜 행동할 준비가 되었는가

## 3. Hero를 구체적으로 서술한다.
반드시 포함:
- Hero가 만들어야 할 첫인상
- Headline의 역할
- Supporting Message의 역할
- Hero Visual의 역할
- Primary CTA 1개
- Secondary Action의 처리 방식

## 4. Scroll Narrative를 만든다.
페이지 구조를 단순히 섹션 이름으로 나열하지 않는다.

각 구간마다:
고객의 현재 질문
→ 이 섹션이 주는 답
→ 보여줄 실제 Fact / Proof
→ 추천 시각 구조
→ 다음 질문으로 넘어가는 이유

를 연결한다.

## 5. 구조적 레이아웃 언어를 명시한다.
“고급스럽게”, “깔끔하게”처럼 추상적으로만 작성하지 않는다.

필요에 따라 다음과 같이 구체화한다.
- Large image-led hero
- Split screen
- Asymmetric editorial grid
- Full-bleed visual
- Connected timeline
- Large numeric statement
- Before / After comparison
- Sticky narrative
- Typography-only statement
- Message-like review layout

카드는 기본 레이아웃으로 사용하지 않는다. 반복 비교가 필요한 콘텐츠에만 제한적으로 사용한다.

## 6. 페이지 전체의 Visual Rhythm을 정의한다.
같은 명도, 같은 섹션 높이, 같은 박스 구조를 반복하지 않는다.

예:
White Hero
→ Information-dense Pricing
→ Large Image Service Section
→ Dark Trust Section
→ Bright Before / After
→ Soft Neutral Process
→ Strong Contrast Final CTA

## 7. FACT는 절대 변경하지 않는다.
Creative Brief가 창의적인 서술을 사용하더라도 다음은 임의 생성하거나 변경하지 않는다.
- 가격
- 서비스 범위
- 정책
- 운영 지역
- 실적
- 실제 후기 여부
- 실제 인증
- 실제 경력
- 실제 서비스 프로세스

## 8. DESIGN MOCK ASSET을 구분한다.
디자인 검토 단계에서는 다음을 가상으로 생성할 수 있다.
- Hero Image
- Service Image
- Before / After
- Mock Review
- Sample Name

단, 반드시 DESIGN MOCK ASSET으로 취급한다.
실제 사업 사례나 고객 후기라고 주장하지 않는다. 실제 공개 전 실제 자료로 교체한다.

## 9. 범용 UI/UX는 기존 Skill을 우선 활용한다.
Creative Build Brief는 프로젝트 고유의 전략, 구조, 고객 심리, 정보 우선순위, 경험, 콘텐츠 관계를 정의한다.

다음 범용 영역은 설치된 UI/UX Skill을 우선 활용한다.
- Typography 세부 규칙
- Color system
- Spacing
- Grid
- Component quality
- Accessibility
- Responsive fundamentals
- UI anti-pattern
- Frontend best practice

단, Skill이 확정된 FACT나 전략을 변경해서는 안 된다.

## 10. 마지막 감정을 한 문장으로 정의한다.
예:
“사용자가 마지막에 ‘가격도 이해했고, 추가비도 미리 안내받을 수 있으며, 결과가 부족하면 확인까지 해주는 곳이니 견적을 한번 받아봐도 되겠다’고 느껴야 한다.”

# 권장 출력 형식

## CREATIVE BUILD BRIEF

### Project Experience
사이트 전체가 어떤 경험이어야 하는지 서술한다.

### Audience State
방문자가 사이트에 들어올 때 가진 문제, 질문, 욕구, 불안을 설명한다.

### Conversion Goal
Primary Conversion과 Secondary Action의 관계를 설명한다.

### Hero Direction
첫 화면의 메시지, 이미지, CTA, 감정 목표를 설명한다.

### Scroll Narrative
스크롤에 따라 고객의 질문이 어떻게 변화하고 각 구간이 어떤 답을 제공하는지 설명한다.

### Section Art Direction
주요 섹션별로 레이아웃, 이미지 역할, 숫자, 타이포, 시각적 대비 방식을 설명한다.

### Visual Rhythm
페이지 전체의 명도, 이미지 비중, 정보 밀도와 섹션 리듬을 설명한다.

### Motion Direction
Design Mode에 맞는 모션의 역할과 강도를 설명한다.

### Mobile Priority
모바일에서 반드시 유지해야 할 정보 순서와 행동 우선순위를 설명한다.

### FACT / MOCK Boundary
실제 사실과 DESIGN MOCK ASSET을 구분한다.

### Success Condition
사이트 마지막에 사용자가 가져야 할 판단과 감정을 한 문장으로 정의한다.

# 제작 전달 우선순위
1. 확정 FACT
2. Creative Build Brief
3. 선택된 구조 / Design Direction
4. UI/UX Skill의 범용 디자인 지식
5. 구현 세부 판단

충돌이 생기면 위 순서를 우선한다.
