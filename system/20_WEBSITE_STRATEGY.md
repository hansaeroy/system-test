# 홈페이지 전략 및 구조 선택 규칙

## 목적
온보딩에서 확보한 사업 사실을 기반으로 고객이 실제로 행동하도록 만드는 홈페이지 구조를 결정한다.

이 단계에서는 디자인 스타일보다 `무엇을 어떤 순서로 보여줄 것인가`를 먼저 결정한다.

## 1. 사이트의 Primary Conversion을 하나 정한다.
예:
- 견적 요청
- 상담 신청
- 예약
- 전화 문의
- 구매
- 방문 신청

Primary Conversion은 페이지 전체에서 하나를 중심으로 한다.
Secondary Action은 존재할 수 있지만 Primary Conversion과 경쟁하지 않는다.

## 2. 고객의 첫 번째 질문을 찾는다.
대표 유형:
- PRICE: 얼마인가?
- TRUST: 여기 잘하는 곳인가?
- FIT: 내 문제를 해결할 수 있나?
- RESULT: 결과가 어떻게 나오나?
- PROCESS: 어떻게 진행되나?
- BRAND: 어떤 브랜드인가?

## 3. 고객의 의사결정 장애물을 순서대로 정리한다.
기본 논리:

고객 문제
→ 즉각적인 답
→ 다음 의심
→ 증거
→ 다음 의심
→ 증거
→ 행동

## 4. 구조 유형을 선택한다.

### Conversion Direct
적합: 가격, 범위, 조건을 빨리 알고 싶은 고객

구조 예:
Hero
→ 가격
→ 서비스 범위
→ 추가비
→ 프로세스
→ Proof
→ 후기
→ FAQ
→ CTA

### Proof First
적합: 실력과 결과를 먼저 확인하는 고객

구조 예:
Hero
→ 결과물
→ Before/After
→ 실적
→ 작업 방식
→ 서비스
→ 가격
→ 정책
→ 후기
→ CTA

### Problem Story
적합: 여러 불안과 고민을 하나씩 해결해야 하는 서비스

구조 예:
Hero
→ 문제 1
→ 해결
→ 문제 2
→ 해결
→ 문제 3
→ 해결
→ Proof
→ 가격
→ CTA

### Editorial
적합: 브랜드 이미지와 감성적 인상이 구매 판단에 큰 영향을 주는 경우

구조 예:
Visual Hero
→ Brand Statement
→ Visual Story
→ Service
→ Evidence
→ CTA

### Showcase
적합: 결과물이 핵심 구매 이유인 경우

구조 예:
Hero
→ Featured Work
→ Case
→ Case
→ Case
→ Service
→ Trust
→ CTA

### Sticky Narrative
적합: 과정, 기술, 제품 기능 등을 단계적으로 설명해야 하는 경우

구조 예:
Hero
→ Sticky Explanation
→ Step
→ Step
→ Step
→ Proof
→ CTA

## 5. 하나의 구조에 억지로 맞추지 않는다.
구조는 조합할 수 있다.

예:
- Base: Proof First
- Hero: Problem Story
- Process: Sticky Narrative
- Case: Showcase

## 6. 한 화면 하나의 판단 원칙
각 주요 화면/섹션:
- 핵심 메시지 1개
- Primary CTA 최대 1개

동일 위계의 CTA를 여러 개 병렬 배치하지 않는다.
전화, 카카오톡 등은 필요하면 텍스트 링크, 헤더 유틸리티, 플로팅 상담, 모바일 하단 고정 영역 등 Secondary Action으로 분리한다.

## 7. 섹션 생성 기준
모든 섹션은 다음 질문 중 하나에 답해야 한다.
- 이 서비스는 무엇인가?
- 나에게 맞는가?
- 얼마인가?
- 어디까지 해주는가?
- 왜 믿을 수 있는가?
- 실제 결과는 어떤가?
- 어떻게 진행되는가?
- 문제가 생기면 어떻게 되는가?
- 지금 무엇을 해야 하는가?

답하지 못하는 섹션은 제거를 검토한다.
