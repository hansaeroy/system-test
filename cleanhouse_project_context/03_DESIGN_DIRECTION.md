# 클린하우스 입주청소 — 디자인 브리프 / Visual Exploration 기준

상태: VISUAL EXPLORATION
현재 단계: 실제 화면 디자인 탐색 전
기존 선택안: 폐기 / 참고 금지
Page Architecture: MULTI PAGE

## 1. 이번 단계의 목적

이 문서는 최종 디자인을 말로 확정하는 문서가 아니다.

목적은 클린하우스에 맞는 실제 시각 결과물을 만들기 위한 최소 디자인 브리프를 제공하는 것이다.

이 단계에서는 특정 스타일명, 특정 컬러 토큰, 특정 그리드 수치, 특정 레이아웃 공식을 먼저 고정하지 않는다.

기존에 제작한 A/B/C 프로토타입과 `B / Editorial Trust` 선택은 이번 탐색의 기준으로 사용하지 않는다.
기존 시안은 실험 기록으로만 남기고, 새 시각 탐색에 앵커로 사용하지 않는다.

## 2. 디자인이 해결해야 할 문제

클린하우스 사이트는 다음 문제를 시각적으로 해결해야 한다.

- 전형적인 저가형 청소업체 템플릿처럼 보이지 않아야 한다.
- 첫 화면에서 청결감과 신뢰감이 동시에 느껴져야 한다.
- 가격이 숨겨져 있지 않다는 인상을 줘야 한다.
- 서비스 범위를 어렵지 않게 이해할 수 있어야 한다.
- 실제 결과 이미지가 중요한 신뢰 근거가 되어야 한다.
- 사용자가 많은 정보를 읽지 않아도 핵심 판단이 가능해야 한다.
- 디자인 완성도가 높아도 정보 탐색을 방해하지 않아야 한다.

## 3. 목표 감정

방문자가 느껴야 하는 감정:

- 깨끗하다
- 믿을 수 있다
- 투명하다
- 정돈되어 있다
- 과하게 상업적이지 않다
- 어느 정도 고급스럽다
- 맡겨도 불안하지 않다

## 4. 피해야 할 인상

- 청소 전단지
- 저가형 지역 서비스 템플릿
- SaaS 랜딩페이지
- 카드와 아이콘 반복
- 지나치게 귀엽거나 가벼운 톤
- 과도한 프리미엄 연출로 정보가 묻히는 구성
- 과도한 다크 테마
- 과도한 모션 중심 사이트

## 5. Visual Exploration 범위

전체 사이트를 먼저 만들지 않는다.

다음 4개 대표 화면/구간만 실제 시각 시안으로 탐색한다.

### 1) Hero
검증할 것:
- 브랜드 첫인상
- 청결감
- 신뢰감
- 타이포그래피 수준
- 이미지 역할
- CTA 위계

### 2) Price
검증할 것:
- 가격 정보를 아름답고 빠르게 읽히게 만드는 능력
- 숫자 위계
- 정보 밀도 처리
- 카드 의존 여부

### 3) Trust / Proof
검증할 것:
- `1,200+` 실적을 신뢰 장면으로 만드는 능력
- 숫자와 이미지의 관계
- 명도/밀도 전환

### 4) Before / After
검증할 것:
- 실제 결과를 강하게 보여주는 능력
- 이미지 비율과 크롭
- 비교 방식
- Proof로서의 설득력

## 6. 시안 생성 규칙

- 최소 2안, 권장 3안을 만든다.
- 각 안은 이름만 다르고 구조가 같은 시안이면 실패다.
- Hero만 다르게 만들고 나머지를 같은 패턴으로 재사용하면 실패다.
- 각 안의 Price, Trust, Before / After도 실제 화면 구조가 달라야 한다.
- 공통으로 유지할 것은 사업 FACT와 핵심 메시지뿐이다.
- 컬러, 타이포 조합, 레이아웃, 이미지 비율, 여백 리듬은 탐색 대상으로 남긴다.

## 7. 고정 FACT

디자인 탐색 과정에서도 다음 사업 사실은 변경하지 않는다.

- 브랜드명: 클린하우스 입주청소
- 서비스: 입주청소 / 이사청소
- 기본 가격: 20평 이하 180,000원 / 21~30평 230,000원 / 31~40평 280,000원 / 41~50평 330,000원 / 51평 이상 상담
- 옵션: 냉장고 30,000원 / 세탁기 30,000원 / 오븐 20,000원 / 전자레인지 20,000원
- 추가 비용은 필요한 경우 작업 전에 안내
- 누적 1,200건+ 입주·이사청소 진행
- 서울·경기 중심
- 작업 완료 후 고객 검수
- 미흡 시 사진 접수 후 보완 방문 여부와 일정 협의

## 8. 시안용 자산

실제 자료가 없는 경우 디자인 탐색용 가상 자산 사용 가능.

허용:
- Hero 이미지
- 주거공간 이미지
- 청소 작업 이미지
- Before / After
- 후기 레이아웃용 mock

모든 가상 자산은 DESIGN MOCK ASSET으로 취급한다.
실제 클린하우스 사례나 실제 고객 후기라고 주장하지 않는다.

## 9. 디자인 선택 기준

스타일 이름을 선택하지 않는다.

실제 화면을 보고 다음을 판단한다.

1. 첫 화면에서 신뢰와 청결감이 충분한가?
2. 일반적인 청소업체 템플릿처럼 보이지 않는가?
3. 가격이 빠르게 읽히는가?
4. 타이포그래피 자체가 디자인의 일부로 작동하는가?
5. 이미지가 장식이 아니라 정보와 감정을 전달하는가?
6. `1,200+`가 실제 신뢰 장면으로 작동하는가?
7. Before / After가 충분히 강한가?
8. 화면 리듬이 단조롭지 않은가?
9. 전체 사이트로 확장 가능한가?
10. 실제 서비스 사이트로 사용하기에 과도하지 않은가?

## 10. 선택 방식

최종 선택은 `A / B / C` 같은 스타일 이름으로 하지 않는다.

다음처럼 실제 화면 조합으로 선택한다.

- 선택 Hero
- 선택 Price
- 선택 Trust
- 선택 Before / After

필요하면 서로 다른 시안의 장점을 조합할 수 있다.

선택된 실제 화면이 이후 디자인의 Source of Truth가 된다.

## 11. 다음 단계

1. 이 브리프를 기준으로 실제 Visual Exploration 시안을 만든다.
2. Hero / Price / Trust / Before & After를 화면으로 비교한다.
3. 실제 화면을 보고 선택·수정한다.
4. 선택된 화면에서 Design System을 역추출한다.
5. 그 이후에만 Production Spec을 다시 확정한다.
6. Codex 전체 구현은 그 다음 단계에서 진행한다.

현재 단계에서는 전체 멀티페이지 구현에 들어가지 않는다.
