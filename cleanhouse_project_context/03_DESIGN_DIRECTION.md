# 클린하우스 입주청소 — 디자인 방향

상태: DESIGN SELECTED
현재 단계: 최종 디자인 방향 확정
선택안: B / Editorial Trust
보완 방향: C / Result First의 Before / After 결과 강조 방식 일부 반영

## 1. 최종 승인 디자인 방향
Primary Direction:
- B / Editorial Trust

Secondary Influence:
- C / Result First의 결과 이미지 강조 방식

Design Mode:
- STANDARD base
- Premium Visual Quality
- Editorial Trust
- Light Motion Accent

## 2. Visual Concept
“입주 전 마지막 걱정을 지워주는 깨끗한 시작”

클린하우스는 일반적인 청소업체 템플릿이 아니라, 가격과 결과를 명확히 보여주면서도 브랜드 인상이 남는 편집형 서비스 사이트로 표현한다.

정보 전달력은 유지하되, 대형 타이포그래피·비대칭 구성·큰 숫자·실제 공간 이미지가 주요 시각 장치가 된다.

## 3. 선택 이유
B안을 최종 베이스로 선택한다.

선택 이유:
- A보다 브랜드 인상과 시각적 차별성이 강하다.
- C보다 가격·서비스·신뢰 정보의 전달력이 안정적이다.
- 서비스업에 필요한 신뢰감과 프리미엄한 편집형 표현의 균형이 가장 좋다.
- 멀티페이지 전체로 확장하기에 구조적 유연성이 높다.
- `180,000원`, `1,200+` 같은 핵심 숫자를 강한 시각적 앵커로 사용할 수 있다.
- 밝은 영역과 어두운 영역을 교차시켜 페이지 리듬을 만들기 좋다.

## 4. B에서 유지할 핵심 요소

### Hero
- 대형 타이포그래피 중심
- 이미지와 텍스트의 비대칭 구성
- 텍스트와 이미지가 단순한 50:50 분할이 아니라 서로 긴장감 있게 배치됨
- 첫 화면에서 일반 청소업체보다 브랜드 사이트에 가까운 인상을 만든다.
- Primary CTA는 `청소 견적 요청하기` 하나를 중심으로 둔다.

### Price
- 가격 정보를 단순 카드 묶음으로 만들지 않는다.
- 대표 가격 `180,000원`을 큰 타이포그래피로 먼저 보여준다.
- 나머지 가격은 명확한 인덱스 또는 리스트 구조로 정리한다.
- 시각적 개성과 실용적 가독성을 동시에 유지한다.

### Trust
- `1,200+`를 작은 통계 카드가 아니라 하나의 강한 시각 장면으로 사용한다.
- 작업 이미지와 숫자를 함께 배치해 숫자가 실제 서비스 경험과 연결되어 보이게 한다.
- 다크 섹션을 활용해 페이지 중간에 강한 명도 전환을 만든다.

### Layout Character
- editorial composition
- asymmetric alignment
- large typography
- strong numeric anchors
- image + text interplay
- 밝은 섹션과 어두운 섹션의 대비
- 동일한 카드/Grid 반복 금지

## 5. C에서 차용할 요소

C / Result First 전체 방향을 사용하지는 않는다.

다음 요소만 선택적으로 반영한다.

### Before / After
- B 프로토타입보다 결과 이미지의 비중을 더 크게 가져간다.
- Before / After가 단순 보조 콘텐츠가 아니라 주요 Proof 장면이 되게 한다.
- near full-width 또는 큰 이미지 중심 구성 허용
- 이미지 간 크기·위치 차이, overlap, offset 등을 활용할 수 있다.
- 결과가 설명보다 먼저 인지되게 한다.

### Cases / Results
- Cases 페이지에서는 다른 페이지보다 이미지 비중을 높인다.
- 대표 결과는 작은 갤러리 카드보다 큰 이미지 중심으로 보여준다.
- 실제 작업 결과가 충분히 확보되면 Result First의 몰입감을 부분적으로 확장할 수 있다.

## 6. 사용하지 않을 방향

### A에서 제외
- 지나치게 안전하고 균일한 화이트 중심 구성
- 모든 정보를 정돈된 표와 좌우 분할만으로 처리하는 방식
- 브랜드 인상이 약해지는 과도한 미니멀리즘

### C에서 제외
- 사이트 전체를 다크톤으로 구성하는 방식
- 이미지가 정보보다 지나치게 앞서는 구성
- 가격과 서비스 정보의 탐색성을 떨어뜨리는 과도한 overlay
- 컨셉이 실용적 전환을 압도하는 구성

## 7. 전체 멀티페이지 확장 원칙

Page Architecture:
- MULTI PAGE

페이지별 시각 역할:

### Home
- B / Editorial Trust를 가장 직접적으로 적용
- 비대칭 Hero
- 대표 가격 숫자
- 1,200+ 신뢰 장면
- 대표 Before / After
- 상세 페이지로 연결되는 전환 허브

### Service
- 큰 공간 이미지 + 편집형 텍스트 배치
- 서비스 내용을 작은 카드 반복으로 설명하지 않는다.
- 주방, 욕실, 창틀, 바닥, 수납공간 등을 공간 경험처럼 보여준다.

### Price
- 정보 가독성을 가장 우선한다.
- 큰 숫자와 명확한 가격 리스트를 결합한다.
- Editorial 감도는 유지하되 정보 탐색을 방해하지 않는다.

### Cases / Reviews
- C / Result First의 영향이 가장 강하게 적용되는 페이지
- Before / After와 실제 작업 이미지를 크게 사용
- `1,200+`와 실제 후기/사례를 강한 Proof로 배치

### Guide / FAQ
- 편집형 타이포와 연결된 Process 구조 사용
- 동일한 단계 카드 6개 반복보다 timeline 또는 connected narrative를 우선한다.

### Estimate
- 가장 단순하고 집중된 전환 페이지
- 장식보다 견적 요청 행동에 집중한다.
- B의 타이포그래피 언어와 브랜드 요소만 최소한으로 유지한다.

## 8. Color Direction
정확한 최종 색상 토큰은 제작설계서 단계에서 UI/UX Skill과 함께 확정한다.

현재 방향:
- 밝은 neutral / warm paper 계열을 기본 캔버스로 사용
- deep ink / charcoal을 강한 대비 섹션에 사용
- green은 Primary CTA 및 핵심 상태 강조에 제한적으로 사용
- B 프로토타입의 editorial contrast를 유지하되, 실제 청소 서비스의 청결감이 약해지지 않도록 조정한다.

## 9. Typography Direction
정확한 scale과 font stack은 제작설계서 단계에서 최종 확정한다.

방향:
- Hero와 핵심 숫자는 큰 display scale
- 본문은 높은 가독성 유지
- 가격·실적 숫자는 일반 Body보다 확실히 큰 위계를 가진다.
- Editorial 느낌을 위해 display와 utility text의 대비를 사용할 수 있다.
- 한국어 가독성을 우선한다.

## 10. Image Strategy
- 실제 주거공간 이미지가 핵심 시각 자산이다.
- Hero, Service, Cases에서 이미지 역할을 구분한다.
- Hero: 깨끗하게 정돈된 결과 공간
- Service: 공간별 청소 범위를 이해시키는 이미지
- Cases: 실제 Before / After와 작업 결과
- Review: 실제 메시지/후기 자료

디자인 검토 단계에서 실제 자료가 없는 경우 DESIGN MOCK ASSET 사용 가능.
실제 공개 전 반드시 실제 자료로 교체한다.

## 11. Motion Direction
Motion Intensity:
- Light / Premium Accent

허용:
- image reveal
- text reveal
- subtle depth movement
- 숫자 강조 transition
- Before / After interaction
- process progression

금지:
- 콘텐츠보다 모션이 먼저 보이는 과도한 animation
- 의미 없는 반복 parallax
- 정보 탐색을 방해하는 scroll hijacking

## 12. CTA Direction
Primary Conversion:
- 견적 요청

원칙:
- 주요 화면/섹션당 Primary CTA 최대 1개
- 전화·카카오톡은 Secondary Action
- 동일 위계의 CTA를 병렬로 반복하지 않는다.
- Home, Price, Cases, Guide의 흐름은 최종적으로 Estimate로 연결한다.

## 13. FACT / MOCK Boundary
확정 FACT는 디자인 때문에 변경하지 않는다.

특히 다음은 고정:
- 실제 서비스
- 실제 가격
- 추가비 조건
- 운영 지역
- 1,200건+ 실적
- 검수·보완 정책
- 실제 프로세스

DESIGN MOCK ASSET 가능:
- Hero Image
- Service Image
- Before / After
- Mock Review
- Sample Name

Mock Asset은 실제 고객 사례로 주장하지 않는다.

## 14. 다음 액션
A/B/C 디자인 탐색은 종료한다.

이후에는 B / Editorial Trust를 최종 디자인 기준으로 사용한다.
C / Result First는 Before / After 및 Cases의 결과 이미지 강화에만 부분 적용한다.

다음 단계:
1. 선택된 디자인 방향을 기준으로 Creative Build Brief 갱신
2. 멀티페이지 전체 제작설계서 확정
3. Codex 전체 구현
4. QA

더 이상 A/B/C 후보 비교 단계로 돌아가지 않는다. 디자인 방향 변경이 필요한 경우 명시적인 재승인 절차를 거친다.
